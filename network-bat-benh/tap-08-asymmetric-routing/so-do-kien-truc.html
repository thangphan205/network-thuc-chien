scripts/1-binh-thuong.sh · scripts/2a-chua-route.sh ip route replace 172.28.8.0/24 via 172.28.18.251
  • SYN và SYN-ACK cùng qua fw-a → fw-a thấy đủ hai chiều, curl 200, giữ nguyên IP thật client
  • fw-b: 0 session, 0 gói INVALID — đây vừa là mốc khỏe (KB1) vừa là kết quả khi chữa gốc bằng sửa route (Thuốc 2a)
  • Hai firewall giữ bảng conntrack riêng, không ai báo cho ai
scripts/2-bat-doi-xung-stateful.sh · trên server ip route replace 172.28.8.0/24 via 172.28.18.252
  • ping thông (luật cho ICMP qua không xét state), curl 000 — chết ngay bước bắt tay
  • fw-a: SYN_SENT [UNREPLIED] · fw-b: 0 session, counter INVALID tăng
  • Không thiết bị nào hỏng riêng lẻ — hỏng ở chỗ đường về đi qua firewall chưa từng thấy SYN
scripts/2b-chua-snat.sh · trên fw-a (khi không sửa được route) iptables -t nat -A POSTROUTING -s 172.28.8.0/24 -d 172.28.18.0/24 -j MASQUERADE
  • Route server vẫn trỏ fw-b — nhưng trả lời tới .251 cùng LAN, đi thẳng về fw-a
  • curl 200, fw-b 0 gói INVALID — đường về tự đối xứng
  • Cái giá: nginx thấy nguồn 172.28.18.251, mất IP thật client. Chữa gốc: sửa route (Thuốc 2a)
